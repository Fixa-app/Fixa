## Belangrijke bugfix: PATCH route quotes/[id]

### Probleem
De PATCH-route op `/api/quotes/[id]` was bij het toevoegen van status-wijzig-functionaliteit per ongeluk **herschreven om alleen nog `status`-updates te accepteren** — generieke veld-updates (job_title, intro_text, disclaimer) werden genegeerd en gaven een 400-error die de front-end niet checkte.

**Gevolgen die dit verklaarde:**
- Klusnaam werd niet opgeslagen bij "Concept opslaan" (bleef `null` in database)
- Backlog-punt "concept verwijderen werkt niet" — bleek dat de route ook **geen DELETE-handler** had

### Fix
Route herschreven om beide te ondersteunen: generieke `{ userId, ...updates }`-destructuring, met status-specifieke validatie/side-effects (approved_at) alleen als `status` in de payload zit. DELETE-handler toegevoegd.

### Aanvullende UX-fix
Scroll-to-error + focus toegevoegd bij lege klusnaam-validatie (browser-achtig gedrag nabouwen voor custom input).

## Client hub — gebouwd, geblokkeerd op DNS

### Database
```sql
ALTER TABLE quotes ADD COLUMN client_token TEXT UNIQUE, ADD COLUMN client_token_expires_at TIMESTAMPTZ;
CREATE TABLE quote_change_requests (id, quote_id, message, created_at);
```

### Gebouwd
- `POST /api/quotes/[id]/token` — genereert/hergebruikt token, 30 dagen geldig
- `GET/POST /api/hub/[token]` — publieke route (geen auth), toont offerte, verwerkt "accepteren" of "wijziging aanvragen" (met vrije tekst, geen per-regel-reacties — bewuste keuze om muggenziften te voorkomen)
- `/[token]` — publieke hub-pagina: offerte-document + sticky actiebar (accepteren / wijziging aanvragen via bottom-sheet)
- "Deel met klant"-knop op quote-detail-pagina, via Web Share API (native deelmenu op mobiel, clipboard-fallback op desktop)

### Blocker ontdekt: app.hifixa.com redirect
`app.hifixa.com` redirect **alle** niet-ingelogde requests (bevestigd: ook `/dashboard` zelf) naar `hifixa.com` — een bewuste, bestaande architectuurkeuze (login verloopt via de marketingsite). Dit blokkeert de publieke hub-route, die per definitie zonder sessie moet werken.

**Besluit**: client hub op eigen subdomein `hub.hifixa.com`, los van de auth-redirect. Code al aangepast:
- Hub-pagina verplaatst van `src/app/hub/[token]/page.tsx` naar `src/app/[token]/page.tsx` (root-level op het toekomstige hub-domein, dus geen `/hub/`-prefix nodig in de URL)
- Share-functie gebruikt nu vaste basis-URL (`NEXT_PUBLIC_HUB_URL` env var, fallback `https://hub.hifixa.com`) i.p.v. `window.location.origin`

**Wacht op**: DNS-toegang via Niek — verzoek verstuurd voor zowel Resend (e-mail) als CNAME voor `hub.hifixa.com`.
