## Request-flow — vanaf nul gebouwd

### Conceptuele uitwerking (belangrijk om te onthouden)
Lange discussie over hoe request zich verhoudt tot quote. Eindmodel:
- Funnel blijft: **Request → Intake → Quote → Job → Invoice**, met Request+Intake samengevoegd in V1
- Request is **geen** vroege-status van een quote — apart concept, eigen tabellen, want anders ontstaat een onhoudbare status-glijbaan
- Pro's workflow tijdens intake: **werk eerst opnemen (foto's, korte titel per probleem), klant pas als laatste stap** — gebaseerd op hoe het in de praktijk altijd gaat (intake/bezichtiging gaat altijd vooraf aan een offerte)
- "Omzetten naar offerte": AI matcht request-item-titels tegen de bestaande `products`-tabel (die al sinds onboarding-parse gevuld is met titel+prijs uit eerder geüploade offertes) — geeft titel+prijs waar een match is, titel-only waar niet

### Database
```sql
CREATE TYPE request_status AS ENUM ('open', 'converted', 'archived');

CREATE TABLE requests (...)  -- company_id, client_id (nullable!), status, converted_to_quote_id
CREATE TABLE request_items (...)  -- title, description, sort_order
CREATE TABLE request_item_photos (...)  -- storage_path

GRANT ALL ON requests, request_items, request_item_photos TO authenticated, service_role;
```

### Storage
- Oude `quote-photos` bucket opgeruimd (bevatte alleen testdata) en vervangen door nieuwe `request-photos` bucket
- **Niet public** — privacy van klantsituaties — dus signed URLs (`createSignedUrl`/`createSignedUrls`, 1 uur geldig) i.p.v. publieke URLs
- Allowed MIME types: `image/jpeg, image/png, image/heic, image/heif` (HEIC/HEIF voor onverwerkte iPhone-foto's)
- Policies: insert (authenticated), select + delete (alleen company members, via join naar `request_items` → `requests`)

### Flow gebouwd
1. **Stap 1** (`/dashboard/requests/new`): meerdere "punten" toevoegbaar, elk met titel + omschrijving + foto's (camera-input, multi-upload, signed URL preview na upload)
2. **Stap 2** (`/dashboard/requests/new/[id]/client`): klant zoeken/aanmaken — vrijwel 1-op-1 hergebruik van bestaande quote-stap-1-logica — rondt de request af
3. **Detail-pagina** (`/dashboard/requests/[id]`): toont klant (met bel/WhatsApp-iconen), items met foto's, en sticky "Omzetten naar offerte"-knop (disabled zonder klant)
4. **Omzetten** (`POST /api/requests/[id]/convert`): AI-call (Claude Sonnet 4.6) matcht items tegen `products`, maakt nieuwe quote + line items aan, markeert request als `converted`, stuurt pro naar quote-stap-2 om prijzen te checken/aanvullen

### API routes nieuw
- `POST /api/requests/create` — nieuwe request + items + foto-koppeling
- `GET/PATCH /api/requests/[id]` — detail ophalen (met signed photo URLs) / klant koppelen
- `POST /api/requests/[id]/convert` — omzetten naar quote met AI-matching
