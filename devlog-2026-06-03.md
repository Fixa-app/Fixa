# Dev log — 3 juni 2026

## Database migratie: statussen en invoices tabel

### Aanleiding
Tijdens het bouwen van de dashboard filled state zijn we de quote statussen doorgelopen vanuit het perspectief van de pro (geld verdienen). Dit leidde tot een opschoning van de DB enum en de aanmaak van de invoices tabel.

---

### Quote statussen

**Beslissingen:**
- `ready_to_send` verwijderd — stond niet in de user stories, geen plek in de UX
- `approved` hernoemd naar `ready_to_schedule` — sluit aan op de actie die de pro moet ondernemen
- Labels zijn nu consistent: DB enum = label in app = filter dropdown label

**Definitieve quote_status enum:**

| DB enum | Label in app | Getoond op dashboard |
|---|---|---|
| `draft` | Draft | ✅ |
| `awaiting_response` | Awaiting response | ❌ |
| `changes_requested` | Changes requested | ✅ |
| `ready_to_schedule` | Ready to schedule | ✅ |
| `declined` | Declined | ❌ |
| `archived` | Archived | ❌ |

**Dashboard toont alleen statussen waar actie op vereist is:** Draft, Changes requested, Ready to schedule.

---

### Invoice statussen

**Beslissingen:**
- Invoice flow is V1 focus: offerte → job → factuur → betaling
- Meerwerk wordt afgehandeld door de pro direct op de invoice (geen aparte offerte vereist)
- `partial_payment` geparkeerd naar V2
- `past_due` wordt automatisch gezet via pg_cron op basis van vervaldatum
- Betalingstermijn default: 30 dagen (instelbaar per bedrijf in latere versie)

**Definitieve invoice_status enum:**

| DB enum | Label in app | Getoond op dashboard |
|---|---|---|
| `draft` | Draft | ✅ |
| `awaiting_payment` | Awaiting payment | ✅ |
| `past_due` | Past due | ✅ |
| `paid` | Paid | ❌ |
| `archived` | Archived | ❌ |

---

### Uitgevoerde migraties

1. **Quote enum** — nieuwe `quote_status` enum aangemaakt, `approved` → `ready_to_schedule`, `ready_to_send` verwijderd
2. **Invoice enum** — nieuwe `invoice_status` enum aangemaakt
3. **Invoices tabel** — aangemaakt met RLS, foreign keys naar `companies`, `quotes`, en `profiles(user_id)`
4. **Triggers** — `set_invoice_due_date` (INSERT) en `update_updated_at` (UPDATE)
5. **RLS policies** — select, insert, update op basis van `company_members`
6. **pg_cron** — job `mark-invoices-past-due` draait dagelijks om 06:00, zet `awaiting_payment` → `past_due` waar `due_date < current_date`
